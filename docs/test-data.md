# テストデータ仕様

システムの動作確認用データです。`pnpm db:seed`（または `pnpm db:reset`）で投入します。実装は `packages/db/seed.ts` と `packages/db/seed/` にあり、**このファイルと内容を一致させます**（機能を足したら両方を更新する）。

> ⚠️ ここにあるパスワードは **開発用の公開情報** です。本番では絶対に使わないでください。

## 使い方

```powershell
pnpm db:seed     # 既存データを全て消して、テストデータを入れ直す（マイグレーション済みであること）
pnpm db:reset    # 全テーブルを作り直す → マイグレーション → seed（Claude Code では /db-reset 経由）
```

- seed は **1 つのトランザクション** で実行します。途中で失敗しても DB は変更されません
- 確認用の SQL の例（件数）: `psql -h localhost -U postgres -d xclone -c "SELECT count(*) FROM posts"`

## 設計方針

- **何度実行しても同じ結果**: 乱数の種・ID を固定しています（ID は `stableUuid('user:alice')` のようにキーから作るので、再実行しても変わりません）
- **日付の基準は「実行した日」**: ダッシュボードの「直近 14 日」などが、いつ実行しても今日を基準に並ぶようにするためです。同じ日に実行すれば完全に同じ結果になります。**毎回同じ日付が欲しいとき（E2E テストなど）は `SEED_BASE_DATE=2026-10-11` を付けて実行**します
- 画面確認・E2E・不具合の再現に必要な **あらゆる状態** を含めます（凍結ユーザー、削除済み投稿、対応状況の違う通報、空状態のユーザーなど）
- パスワードは bcrypt（強度 10）でハッシュ化して保存します。時刻の前後関係（登録前の投稿がない、リプライは親より後、など）は矛盾しないように作っています

## 確認シナリオ（このデータで何が確かめられるか）

| 確認したいこと                  | 使うデータ                                          |
| ------------------------------- | --------------------------------------------------- |
| ログイン・ログアウト            | alice でログイン                                    |
| 凍結ユーザーのログイン拒否      | dave でログイン → 拒否される                        |

| 通知の表示と未読バッジ          | alice でログイン（未読 8）                          |
| 通知のリアルタイム配信          | bob で alice の投稿にいいね → alice の画面に通知    |

## 更新ルール

1. 新しいテーブルや機能を足したら、`seed/` にその確認用データを追加する
2. 上の表（件数・状態・シナリオ）を更新する（件数は `pnpm db:seed` の出力から転記する）
3. `pnpm db:reset` で投入し、エラーなく完了することを確認する
4. 「同じ日に 2 回実行して結果が一致するか」を `SEED_BASE_DATE` を固定して確かめる
