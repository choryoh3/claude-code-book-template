# テストデータ仕様

システムの動作確認用データです。`pnpm db:seed`（または `pnpm db:reset`）で投入します。実装は `packages/db/seed.ts` にあり、**このファイルと内容を一致させます**（機能を足したら両方を更新する）。

> ⚠️ ここにあるパスワードは **開発用の公開情報** です。本番では絶対に使わないでください。

## 設計方針

- **何度実行しても同じ結果**（固定の乱数シード、固定の ID と日時の基準）。再実行時は既存データを消してから投入する
- 画面確認・E2E・不具合の再現に必要な **あらゆる状態** を含める（凍結ユーザー、削除済み投稿、対応状況の違う通報など）
- パスワードは bcrypt でハッシュ化して保存する

## アカウント

| メール             | パスワード    | ハンドル | 用途                       |
| ------------------ | ------------- | -------- | -------------------------- |
| admin@example.com  | `Admin#12345` | @admin   | すべての管理操作           |
| admin2@example.com | `Admin#12345` | @admin2  | 複数管理者・監査ログの確認 |

### 一般ユーザー（user アプリ http://localhost:5173）

共通パスワードは `Password#123`。

| メール                       | ハンドル           | 表示名        | 状態・用途                                         |
| ---------------------------- | ------------------ | ------------- | -------------------------------------------------- |
| alice@example.com            | @alice             | Alice         | メイン確認用。投稿・フォロワーが多い               |
| bob@example.com              | @bob               | Bob           | alice の相互フォロー。リプライ・引用の相手         |

## データ量と内容

| テーブル                    | 件数の目安    | 含める状態                                                                                         |
| --------------------------- | ------------- | -------------------------------------------------------------------------------------------------- |
| users                       | 30 + 管理者 2 | 通常 / 凍結（dave）/ 自己紹介・アイコン・ヘッダーあり・なし                                        |
| posts                       | 約 200        | 通常 / リプライ / 引用 / 画像 1〜4 枚 / **280 文字ちょうど** / 削除済み / 管理者が非表示にしたもの |
| follows                     | 約 120        | alice ↔ bob の相互、一方向、ゼロ（eve）                                                            |
| likes / reposts / bookmarks | 各 50〜150    | alice の投稿に集中するもの、同じ投稿への重複なし                                                   |
| hashtags                    | 約 15         | `#vue` `#claude` `#xclone` など。トレンド集計用に偏りを持たせる                                    |
| notifications               | 約 60         | いいね・リポスト・フォロー・リプライ・メンション。既読 / 未読                                      |
| reports                     | 約 10         | 未対応 / 対応中 / 完了（対応メモあり）。投稿の通報とユーザーの通報                                 |
| audit_logs                  | 約 20         | ユーザー凍結・投稿非表示・通報対応・ロール変更（admin / admin2 による操作）                        |

## 確認シナリオ（このデータで何が確かめられるか）

| 確認したいこと             | 使うデータ                                          |
| -------------------------- | --------------------------------------------------- |
| ログイン・ログアウト       | alice でログイン                                    |
| 凍結ユーザーのログイン拒否 | dave でログイン → 拒否される                        |
| フォロー中タイムライン     | alice でログイン（bob らの投稿が並ぶ）              |
| 空状態の表示               | eve でログイン（タイムラインが空）                  |
| 無限スクロール             | alice のタイムライン（200 件規模）                  |
| 文字数制限                 | 280 文字ちょうどの投稿の表示 / 281 文字の投稿は不可 |
| 通知のリアルタイム配信     | bob で alice の投稿にいいね → alice の画面に通知    |
| 通報フロー                 | carol の投稿を通報 → admin で処理                   |
| 管理者の操作と監査ログ     | admin でユーザー凍結 → 監査ログに記録される         |
| ダッシュボードのグラフ     | 過去 14 日分に分散した投稿・登録日時                |

## 更新ルール

1. 新しいテーブルや機能を足したら、`seed.ts` にその確認用データを追加する
2. 上の表（件数・状態・シナリオ）を更新する
3. `pnpm db:reset` で投入し、エラーなく完了することを確認する
