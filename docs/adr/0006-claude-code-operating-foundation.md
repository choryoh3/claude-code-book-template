# 0006. Claude Code の運用基盤（4 層の情報設計と自走の仕組み）

- ステータス: 採用
- 日付: 2026-10-11

## 背景

AI（Claude Code）に開発作業の大半を任せたい。そのためには、AI が毎回迷わず、品質を保ち、途中で止まっても引き継げる仕組みが必要。
一方、常に読み込まれる `CLAUDE.md` に何でも書くと肥大化し、重要な指示が埋もれて守られにくくなる。

## 決定

**「いつ読み込まれるか」で情報を 4 層に分け**、`CLAUDE.md` には常に必要な最小限だけ（100 行以内）を書く。

| 層  | 場所                | 読み込み                             | 入れるもの                         |
| --- | ------------------- | ------------------------------------ | ---------------------------------- |
| 1   | `CLAUDE.md`         | 常時                                 | 概要・コマンド・構成図・絶対ルール |
| 2   | `.claude/rules/`    | 編集するファイルのパスが一致したとき | 領域ごとの規約                     |
| 3   | `.claude/skills/`   | AI が必要と判断したとき              | 手順書・テンプレート・ドメイン知識 |
| 4   | `.claude/commands/` | 人が `/コマンド` で呼んだとき        | 定型ワークフロー                   |

加えて、AI が自走できるよう次を整備する。

- **agents**: 役割ごとに権限を絞った担当者（レビュー・テスト・DB・UI 確認・調査・不具合調査）。調査を任せてメインの文脈を汚さない
- **hooks**: 規約を「お願い」ではなく「仕組み」で守らせる（保存時の整形、危険コマンド・秘密情報・適用済みマイグレーションの編集のブロック、完了時の型チェックと完了音）
- **MCP**: DB の実データ確認（postgres）、画面操作（playwright）、最新ドキュメント（context7）、GitHub
- **台帳と記録**: `docs/roadmap.md`（次にやること）、`docs/progress.md`（やったこと・判断・次の一手）、`docs/adr/`（なぜそう決めたか）。人が替わっても AI が替わっても、これを読めば再開できる
- **不具合調査**: 構造化ログ（pino の JSON Lines + `requestId`）、`/debug`、`bug-investigator`、`docs/troubleshooting.md`

## 結果

- 良い点: 指示が守られやすく、作業の再現性・引き継ぎやすさが上がる
- 注意点: `CLAUDE.md` に書きたくなったら、まず rules / skills / docs に置けないか考える。hooks の設定変更は新しいセッションから有効
