# 0001. pnpm モノレポにして、管理者アプリとユーザーアプリを分ける

- ステータス: 採用
- 日付: 2026-10-11

## 背景

X のクローンには「一般ユーザー向けアプリ」と「管理者向けアプリ」がある。どちらも同じデータベースを使うが、利用者も権限も大きく違う。
また、画面（Vue）・API（Express）・DB・型定義で同じ情報を何度も書くと、食い違いが起きてバグになる。

## 検討した選択肢

1. **1 つのアプリに管理者機能を同居させる** — 小さく始められる。ただし権限の境界が曖昧になり、管理者機能の脆弱性が一般ユーザー側に波及しやすい
2. **別リポジトリに分ける** — 完全に分離できる。ただし共通の型・DB 定義の共有が大変で、変更の同期が手間
3. **1 つのリポジトリ（モノレポ）で、アプリは物理的に分ける** — 境界は保ちつつ、共通部分を共有できる

## 決定

**選択肢 3（pnpm workspaces のモノレポ）** を採用する。

- `user/` と `admin/` は、それぞれ `client`（Vue）と `server`（Express）を持つ。ポートも別（5173/3000、5174/3001）
- 共通部分は `packages/` に置く: `db`（DB 接続・マイグレーション・seed）、`shared`（Zod スキーマと型）、`ui`（デザイントークンと共通部品）
- **admin と user のサーバーは互いの API を呼ばない**。共有したい処理は `packages/` へ移す
- パッケージ管理は pnpm。依存を重複なく保存でき、高速で、ワークスペース機能が標準で使える

## 結果

- 良い点: 管理者機能の事故が一般ユーザー側に及びにくい。型の共有により client / server のズレを防げる
- 注意点: 共通パッケージの変更は両アプリに影響する。`packages/shared` を変えたら両方の型チェックとテストを通すこと
